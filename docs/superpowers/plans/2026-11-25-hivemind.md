# HiveMind Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local, single-user browser app that runs a fixed ~45-min daily brain-training session with adaptive drills, spaced review of the user's own material, and a weekly fixed benchmark showing Day 1 vs now.

**Architecture:** Static HTML + ES-module JavaScript served from `127.0.0.1:8742` by Python's `http.server`. Pure logic (staircase, SM-2, day keys, store validation, session steps, scoring) lives in DOM-free modules tested with `node --test`; screens and drills render into a container with small DOM helpers. All data is one JSON document in `localStorage`.

**Tech Stack:** HTML, CSS, vanilla JS (ES modules), Node 22 built-in test runner, Python 3.12 `http.server`. No npm dependencies.

**Spec:** `docs/superpowers/specs/2026-11-25-hivemind-design.md`

## Global Constraints

- No npm dependencies. `package.json` exists only for `"type": "module"` and `"test": "node --test"`.
- Server: port **8742**, bound to **127.0.0.1**, `.js` served as `text/javascript`.
- Storage: `localStorage` key **`hivemind:v1`**, `version: 1`.
- Staircase: correct **+0.15**, wrong **−0.85**, level clamped to `[1, maxLevel]`; integer part = difficulty tier.
- Spaced repetition: SM-2; reviews capped at **100 per day**.
- Day boundary **04:00 local time**. Dates stored as `'YYYY-MM-DD'` day keys.
- Benchmark every **7 days**, fixed parameters, never adapts.
- Backup nag when last backup (or install, if never backed up) is **≥ 7 days** ago.
- Person photos downscaled to **96×96 JPEG**.
- Session order fixed: `benchmark` (when due) → `cue` → `reviews` → `math` → `kim` → `changed` → `where` → `span` → `cups` → `palace`. Pause between steps only; no skip/reorder.
- Modules must not touch `document`, `window` or `localStorage` at import time (tests import them in Node).
- Keyboard operable, visible focus, readable contrast; `prefers-reduced-motion` disables decorative motion only (drill timing/motion stays).
- Visual style: load the `ui-ux-pro-max` and `hallmark` skills when writing `css/style.css` (Task 5); keep the design to CSS variables in that one file.
- Target browsers: Chrome/Edge on Windows.
- Every commit: `git add -A && git commit -m "<message>"`.

## Review Focus

1. **Saved data unreadable on load** (corrupted, hand-edited, wrong shape) → raw data preserved under `hivemind:v1:corrupt-<timestamp>`, error banner shown, never silently overwritten. → Task 3 `corrupt saved data is preserved…`, `valid JSON with wrong shape…`.
2. **Wrong file chosen for import** (not JSON, other version, missing arrays, bad card) → rejected with a message, current data untouched. → Task 3 `parseImport rejects…` tests.
3. **Storage full on save** (many photos) → error shown, previous saved value intact. → Task 3 `save reports quota failure…`.
4. **Coming back after days away** with hundreds of due cards → today's reviews capped at 100, streak 0, benchmark due if ≥ 7 days. → Task 2 `dueCards … capped at 100`; Task 4 streak and benchmark tests.
5. **Browser closed mid-session / training after midnight** → reopening the same day resumes at the next unfinished step; 00:00–03:59 counts as the previous day. → Task 4 `resume skips steps already done today`; Task 2 `dayKey before 4am…`.

### Task 3: Store — load, save, validate, import/export

**Files:**
- Create: `js/store.js`
- Test: `test/store.test.js`

**Interfaces:**
- Consumes: `newCard` (tests only).
- Produces:
  - `KEY = 'hivemind:v1'`
  - `State = {version: 1, createdAt: string, palace: string[], cards: Card[], drills: {[id]: {level: number, history: {day, accuracy, ms, level, wpm?}[]}}, sessions: {day, plan: string[], done: string[], completed: boolean}[], benchmarks: {day, scores: {[testId]: number}}[], lastBackupAt: string|null}`

  - `exportJson(state) → string`, `parseImport(text) → {ok: true, state} | {ok: false, error}`

### Task 4: Session logic — steps, resume, streak, due checks

**Files:**
- Create: `js/session.js`
- Test: `test/session.test.js`

**Interfaces:**
- Consumes: `defaultState` (Task 3), `daysBetween` (Task 2).
- Produces (all pure, return new state objects):
  - `DRILLS = ['math', 'kim', 'changed', 'where', 'span', 'cups', 'palace']`
  - `benchmarkDue(state, today) → boolean` — no benchmarks, or last one ≥ 7 days ago.
  - `buildSteps(state, today) → string[]` — if today has a session record: its `plan` minus `done` (`[]` when `completed`). Otherwise the fresh plan: `['benchmark' if benchmarkDue, 'cue', 'reviews', ...DRILLS]`.
  - `markDone(state, stepId, today) → State` — creates today's record with `plan = buildSteps(state, today)` if missing; appends `stepId` to `done`; sets `completed` when every `plan` step is in `done`.
  - `recordDrill(state, id, {correct, total, ms, level, wpm?}, today) → State` — `drills[id].level = level`; pushes `{day, accuracy: correct/total, ms, level}` (+ `wpm` when given).
  - `streak(state, today) → number` — consecutive completed days ending today, or ending yesterday if today isn't completed.
  - `backupDue(state, today) → boolean` — `daysBetween(lastBackupAt ?? createdAt, today) >= 7`.
